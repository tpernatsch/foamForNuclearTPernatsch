Description

In Case 6, we complete our (simplified) thermo-mechanical analysis of a single fuel rod slice by adding two final missing critical components: the fission gas behavior and the swelling. Fission gas behavior is one of the most complicated aspects of fuel performance. In OFFBEAT, we incorporate SCIANTIX, a standalone 0D code developed at PoliMi, as our state-of-the-art fission gas behavior module. SCIANTIX treats the diffusion of gas atoms (generated by fission) in the fuel grains, and predicts the amount of gas dissolved in the grain or trapped in bubbles at grain boundaries. It includes also a grain boundary model that can predict the size of the grain boundary bubbles depending on the gas influx, fuel temperature and hydrostatic stress. Once saturation thresholds are reached, gases are partially released from the grain boundary bubbles, a phenomenon known as Fission Gas Release (fgr). This can have a significant impact on the gap pressure and gap conductance - notably, Xenon and Krypton have lower thermal conductivities compared to Helium. Additionally, the growth or shrinkage of intra- and intergranular bubbles determines the gaseous fuel swelling, the larger component of fuel swelling if compared to solid swelling.

To take the swelling into account in the mechanic strain/stress balance, this simulation also activates the swelling model for both UO2 fuel and the cladding material. For the fuel, we use the UO2FRAPCON model, which incorporates a burnup dependent correlation for the solid swelling and receives information about gaseous swelling from SCIANTIX. For the cladding, we use the default swelling correlation. Note that for the cladding, swelling has nothing to do with the fission process per se or with the fission gas behavior. It is a somewhat different phenomenon referred to often as growth and due to the impact of fast neutrons with the Zircaloy cristallographic structure. This growth manifests as an axial elongation and radial thinning of the cladding.

Tasks

  1. Create the folder. Either copy Case6 in your working directory or duplicate the Case5 folder and rename it to Case6 for this new simulation.
  2. Update Case6. In particular:
    • Activate the fgr module by selecting SCIANTIX in the solverDict file. This requires creating and setting up a separate file in the Case folder named input_settings.txt for SCIANTIX inputs. See Code snippet below. Take the time to appreciate how many different options enter into play when using a fgr module, affecting (in different degrees) the result of the simulation.
    • Activate the swellingModel for the fuel. Identify the swellingModel keyword in the fuel subdictionary within the materials section of the constant/solverDict file. Select the UO2FRAPCON model which predicts the solid swelling component and receives gaseous swelling data from SCIANTIX.
    • Activate the swellingModel for the clad. Identify the swellingModel keyword in the cladding subdictionary within the materials section of the constant/solverDict file. Select the UO2FRAPCON model which predicts the solid swelling component and receives gaseous swelling data from SCIANTIX.
    • Modify fuelOuter patchProbe. Add the new fields interfaceP and hGap (i.e. the gap conductance) for the fuelOuter patchProbe in the functions section of the system/controlDict file.
  3. Run OFFBEAT Simulation. Execute the OFFBEAT simulation* with your updated 'case6'. You can plot the results of the simulation using the provided plot.py Python script.
  4. Extract data and transform them for MATLAB. Find and extract** the data stored at postProcessing/fuelCenterline/0/T (temperature at the center of the fuel over time), at postProcessing/fuelOuter/0/gapWidth (gapWidth at the outer fuel surface over time), at postProcessing/fuelOuter/0/interfaceP (contact pressure at the outer fuel surface over time), and postProcessing/fuelOuter/0/hGap (gap conductance at the outer fuel surface over time).
  5. Copy data in MATLAB grader.

*NOTE: after you input the data and before running OFFBEAT, you need to set up the OpenFOAM geometry and create the mesh. For a 1D or 2D rod, the blockMeshDict file that is read by the blockMesh utility in order to create the mesh can be created with the rodMaker.py Python script provided within the case folder. For simplicity, all the required steps (from the creation of the geometry with rodMaker to running OFFBEAT) are included in the Allrun bash script that you can find in the folder and that can be conveniently run from terminal. If you need to start over for a new simulation, you can reset the folder using the Allclean bash script.

**NOTE: you can either extract the data manually following the instructions in class or use the extractData bash script for simplicity.
