11 //- Correct turbulence. What about this copy-setting fuss? Well, the standard
12 // OpenFOAM turbulence models (e.g. kEpsilon) do not limit the phase fraction
13 // before constructing the epsilon and k equations. This means that if a phase
14 // fraction happens to be 0 somewhere, it will end up causing some null
15 // entries in the k or epsilon matrices (...).
16 // The solutions are: 1) copy some of the standard kEpslion models and make
17 // them part of FFSEulerFoam and make the changes directly in the turbulence
18 // classes; 2) limit the phase fractions before solving the turbulence models
19 // and then reset them to the un-limited values cached before. Option 1)
20 // is a NO-NO as I don't want to break compatibility with standard OpenFOAM
21 // stuff and I want to avoid code duplication too (as if "code duplication"
22 // is a concern in a code that is 22k+ lines without even counting the
23 // underlying OpenFOAM library)
