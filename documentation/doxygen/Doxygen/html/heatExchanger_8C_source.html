123 /*
124 
125 Theoretical explanation & implementation
126 
127 I assume that the wall separating the two fluids (which might as well be
128 two-phase mixtures) has a certain thermal conductance Hw (provided by the
129 user, which for e.g. a planar sheet of metal, or a thin-walled tube,
130 reduced to Hw = thermal conductivity/wall thickness) and that can be
131 characterised by two surface temperatures, one on the primary side (I will
132 call it Tp) and one on the secondary side (Ts). The THX field that is being
133 passed is exactly the HX surface temperature, so that, it those mesh cells
134 that belong to the primary cellZone, it will be Tp, and Ts in the mesh
135 cells that belong to the secondary. The key idea is to set Tp and Ts
136 so to ensure heat flow (flux to, as I assume the same HX volumetric area
137 on both the primary and secondary sides) conservation across the HX wall.
138 Furthermore, I assume that the HX wall has no thermal inertia per-se
139 (even though I suppose it would not be overly complicated to model that as
140 well, given the current framework). For exaple, let us focus on the primary
141 side. The heat flux through the wall must be equal to the heat flux
142 through the fluid. For a two-phase mixture, I assume that the heat is
143 distributed between the two phases (labelled 1 and 2) according to the
144 fluidPartitionModel (the frac variables seen elsewhere in the code).
145 In particular the heat flux from the secondary side of the wall to the
146 primary will be:
147 
148 Q_(s->p) = Hw*(Ts-Tp) (1)
149 
150 while the heat flow from the primary wall surface to the primary two-phase
151 mixture will be:
152 
153 Q_(p->mix) = f1p*H1p*(Tp-T1p)+f2p*H2p*(Tp-T2p) (2)
154 
155 in which the p subscript of all the quantities on the right refers to them
156 being the values of the fluid mixture on the primary side. This heat flux
157 repartition is the same one used for powerModels and passiveStructure source
158 terms elsewhere in the code. By equating (1) and (2) to ensure flux
159 conservation, we can obtain an expression that relates the secondary side wall
160 temperature Ts to the primary wall temperature Ts as well as two-phase mixture
161 properties on the primary side. In particular, if we consider the expression
162 for both wall sides, we obtain the following system of two equations for two
163 unknowns (Tp, Ts).
164 
165 Ts = ((Hw+f1p*H1p+f2p*H2p)/Hw)*(Tp) - (f1p*H1p*T1p+f2p*H2p*T2p)/Hw (3)
166 Tp = ((Hw+f1s*H1s+f2s*H2s)/Hw)*(Ts) - (f1p*H1s*T1s+f2s*H2s*T2s)/Hw
167 
168 The solutions to this system of equations consist of:
169 
170 Tp = (Bp*As+Bs)/(Ap*As-1) (4)
171 Ts = (Bs*Ap+Bp)/(As*Ap-1)
172 
173 with (i=p or i=s):
174 
175 Ai = (Hw+(f1i*H1i+f2i*H2i))/Hw
176 Bi = (f1i*H1i*T1i+f2i*H2i*T2i)/Hw
177 
178 Oh, guess what are HT and H being passed to the correct function? In the
179 onePhase solver version these are:
180 
181 HT = H*T
182 H = H
183 
184 with H being the fluid-structure heat transfer coeff and T the fluid
185 temperature. In the two-phase version:
186 
187 HT = f1*H1*T1+f2*H2*T2
188 H = f1*H1+f2*H2
189 
190 So this whole framework applies without issues to both the onePhase and
191 twoPhase solvers. For clarity I will call the arguments passed to the correct
192 as sumH (=H) and sumHT (=HT). One thus always has:
193 
194 Ai = (Hw+(sumHi))/Hw (5)
195 Bi = (sumHTi)/Hw
196 
197 Now, again, what is the deal with the subscript i? Well, I remind you that it
198 simply means on which side of the HX wall I am evaluating the variable. Let us
199 make an example. Let us assume we want to compute T on the primary side (thus
200 Tp), and I doing this cell-by-cell. Let us assume we are in cell celli, which
201 belongs to the primary. By accessing the fields sumHT[celli] and sumH[celli] I
202 am accessing what correponds to sumHTp and sumHp from the perspective of the
203 subscripting of equations 4 and 5. But so, how do we access the variables
204 sumHT and sumH in the cell 'opposite' to the primary, on the other side of the
205 wall, in the secondary cell zone? Well, that is what the mapping is for. In
206 particular, without going into the details of how the mapping was constructed (
207 which you can figure out from some comments here and there in the constructor),
208 the name extensions of the mapped variables in the code below (i.e. pOs or sOp)
209 stand for primary over secondary, secondary over primary respectively. What
210 that means is that, if a cell cellip on the primary side corrsponds to a cell
211 cellis on the secondary side, accessing HTsOp[cellip] will yield the value
212 that HT has in cellis on the secondary, namely HT[cellis]. Conversely,
213 accessing HTpOs[cellis] will yield HT[cellip]. Now, if it was just about an
214 indexing change, why used meshToMesh mapping? Well the point is that the the
215 two meshes of the heat exchanger could be non-conformal, so that you loose a
216 clear primary-secondary correspondence between individual cells. Plus, even if
217 mesh were conformal, I see no point in not using already existing OpenFOAM
218 mechanics. Either way, this should help you understand to some degree the
219 implementation of the correct function. Lastly though, THX
220 is the surface temperature of the heat exchanger, which is set by the correct.
221 In particular, THX = Tp in the primary and THX = Ts in the secondary. By
222 considering this, as well as the form of the system of equations 4, it should
223 be easy to understand the double-loop implementation for setting THX.
224 */

226 void Foam::heatExchanger::correct
227 (
228  const volScalarField& HT,
229  const volScalarField& H,
230  volScalarField& THX
231 )
232 {
233  // Get secondary side heat transfer information
234  if (!constructed_)
235  {
236  constructSecondaryHX(constructed_);
237  }
238 
239  const fvMesh& sMesh_ = mesh_.time().lookupObjectRef<fvMesh>(this->getOrDefault<word>("secondaryRegion", mesh_.name()));
240 
241  volScalarField sH
242  (
243  sMesh_.foundObject<volScalarField>("htc")
244  ? sMesh_.lookupObject<volScalarField>("htc")
245  : sMesh_.lookupObject<volScalarField>("htc.liquid.structure")
246  );
247  volScalarField sHT
248  (
249  sMesh_.foundObject<volScalarField>("htc")
250  ? sMesh_.lookupObject<volScalarField>("htc")*sMesh_.lookupObject<volScalarField>("T")
251  : sMesh_.lookupObject<volScalarField>("htc.liquid.structure")*sMesh_.lookupObject<volScalarField>("T.liquid")
252  );
253 
254  //If twoPhase, correct the herat transfer parameters to account for both phases
255 
256  if (sMesh_.foundObject<volScalarField>("htc.vapour.structure"))
257  {
258  const volScalarField& sT2 = (sMesh_.lookupObject<volScalarField>("T.vapour"));
259  const volScalarField& sH2=(sMesh_.lookupObject<volScalarField>("htc.vapour.structure"));
260  sHT+=sH2*sT2;
261  sH+=sH2;
262  }
263 
264  scalarField HTpOs=mappingPtr_->mapTgtToSrc(HT.internalField());
265  scalarField HTsOp = mappingPtr_->mapSrcToTgt(sHT.internalField());
266  scalarField HpOs = mappingPtr_->mapTgtToSrc(H.internalField());
267  scalarField HsOp = mappingPtr_->mapSrcToTgt(sH.internalField());
268 
269  //- The max against 1e-69 is just to avoid the case in which the
270  // heat transfer coefficient on both side is 0 (which results in
271  // Ap*As = 1.0), a case in which no heat is to be transferred via the HX
272  // but that would result in a division by 0 if not accounted for. Please
273  // note that in such a scenario THX is set to 0 yet it does not matter
274  // as said earlier, this only happens where the heat transfer coefficient
275  // 0 or very close to it
276  forAll(primaryCells_, i)
277  {
278  const label& celli(primaryCells_[i]);
279  scalar Ap((Hw_+H[celli])/Hw_);
280  scalar Bp(HT[celli]/Hw_);
281  scalar As((Hw_+HsOp[celli])/Hw_);
282  scalar Bs(HTsOp[celli]/Hw_);
283  THX[celli] = (Bp*As+Bs)/max(Ap*As-1.0, 1e-69);
284  }
285 
286  //In the new approach, there is no primary/secondary distinction anymore, as a dual-mesh handling is been performed
287  //This means that each side is handled on a separate mesh, hence in each mesh I only care about setting the primary cells
288 
289  // forAll(secondaryCells_, i)
290  // {
291  // const label& celli(secondaryCells_[i]);
292  // scalar Ap((Hw_+HpOs[celli])/Hw_);
293  // scalar Bp(HTpOs[celli]/Hw_);
294  // scalar As((Hw_+H[celli])/Hw_);
295  // scalar Bs(HT[celli]/Hw_);
296  // THX[celli] = (Bs*Ap+Bp)/max(As*Ap-1.0, 1e-69);
297  // }
298 
299  //- Kinda useless but whatever, at least the fields looks nicer in paraView
300  // if you set the boundaries
301  THX.correctBoundaryConditions();
302 }

304 void Foam::heatExchanger::constructSecondaryHX(bool& constructed)
305 {
306  Info<< "Creating heatExchanger: " << thisDictionary_.dictName() << endl;
307 
308  // sMesh_.reset(const_cast<fvMesh*>(&(mesh_.time().lookupObject<fvMesh>(this->getOrDefault<word>("secondaryRegion", mesh_.name())))));
309  const fvMesh& sMesh_ = mesh_.time().lookupObjectRef<fvMesh>(this->getOrDefault<word>("secondaryRegion", mesh_.name()));
310  //- Read secondary cellZones and their cells
311  secondaryCells_ = sMesh_.cellZones()[this->get<word>("secondary")];
312 
313  //- Calculate displacement vecdtor that, if applied to the primary
314  // cellZone, would translate it to the secondary cellZone. This assumes
315  // that the cellZones have the same shape and volume. If that is not
316  // the case, a check is done afterwards (currently only on the volume, not
317  // on the shape, which I will implement via comparing bounding boxes at
318  // some point)
319  vector pCOV(vector::zero);
320  vector sCOV(vector::zero);
321  const vectorField& primC(mesh_.C());
322  const scalarField& primV(mesh_.V());
323  const vectorField& secC(sMesh_.C());
324  const scalarField& secV(sMesh_.V());
325  scalar pV(0);
326  scalar sV(0);
327  forAll(primaryCells_, i)
328  {
329  const label& celli(primaryCells_[i]);
330  pCOV += primV[celli]*primC[celli];
331  pV += primV[celli];
332  }
333  reduce(pCOV, sumOp<vector>());
334  reduce(pV, sumOp<scalar>());
335  pCOV /= pV;
336  forAll(secondaryCells_, i)
337  {
338  const label& celli(secondaryCells_[i]);
339  sCOV += secV[celli]*secC[celli];
340  sV += secV[celli];
341  }
342  reduce(sCOV, sumOp<vector>());
343  reduce(sV, sumOp<scalar>());
344  sCOV /= sV;
345  vector delta(pCOV-sCOV);
346  scalar errV((pV-sV)/pV);
347  if ((pV-sV)/pV >= 1e-2)
348  {
349  FatalErrorInFunction
350  << "Primary and secondary zone volumes differ by " << errV
351  << exit(FatalError);
352  }
353  Info<< "Heat exchanger " << thisDictionary_.dictName() << " mapping: applied "
354  << "translation of " << delta << " m" << endl;
355 
356  //- Read mesh geometric data
357  const pointField& pointsRef(sMesh_.points());
358  const faceList& facesRef(sMesh_.faces());
359  const cellList& cellsRef(sMesh_.cells());
360 
361  //- Init new mesh geometric data
362  pointField points(pointsRef.size());
363  faceList faces(facesRef.size());
364  cellList cells(cellsRef.size());
365 
366  //- Create translated mesh
367  // First, copy all points and apply translation
368  forAll(points, i)
369  {
370  points[i] = pointsRef[i] + delta;
371  }
372 
373  //- Set faces, cells as copies of the original indexing (yet the indexing
374  // applies to the translated points, so all the resulting faces and cells
375  // will result translated as well)
376  forAll(faces, i)
377  {
378  faces[i] = facesRef[i];
379  }
380  forAll(cells, i)
381  {
382  cells[i] = cellsRef[i];
383  }
384 
385  //- Assemble new translated mesh
386  autoPtr<fvMesh> translatedMeshPtr;
387  translatedMeshPtr.reset
388  (
389  new Foam::fvMesh
390  (
391  IOobject
392  (
393  "translatedMesh",
394  mesh_.time().constant(),
395  mesh_.time(),
396  IOobject::NO_READ,
397  IOobject::NO_WRITE
398  ),
399  std::move(points),
400  std::move(faces),
401  std::move(cells)
402  )
403  );
404  fvMesh& translatedMesh = translatedMeshPtr();
405 
406  //- Assemble mapping
407  mappingPtr_.reset
408  (
409  new meshToMesh
410  (
411  translatedMesh,
412  mesh_,
413  Foam::meshToMesh::interpolationMethod
414  (
415  this->lookupOrDefault
416  (
417  "interpolationMethod", 2
418  )
419  ),
420  Foam::meshToMesh::procMapMethod::pmAABB,
421  false
422  )
423  );
424  // I do not care about the translatedMesh anymore after this point, I only
425  // needed the mapping!
426  translatedMeshPtr.clear();
427 
428  constructed = true;
429 }
